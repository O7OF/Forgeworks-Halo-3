# ForgeWorks Studio v2.3.3 Technical Changelog

## Summary of Fixes: ASS v3 Structure Compiler Fatal Error Hotfix

ForgeWorks Studio v2.3.3 addresses a critical fatal compilation crash encountered in Halo 3's `tool_fast.exe structure` pipeline when compiling `.ass` level geometry.

---

### 1. Fix ASS v3 Vertex Node Influences & Texcoords Negative Count Fatal Crash

#### Problem & Symptoms
When running the 1-Click Compiler or exporting level structure `.ass` files, `tool_fast.exe` halted compilation with fatal errors:
```
=== starting import of structure 'levels\multi\custom_canvas\custom_canvas'parsing scene: data\levels\multi\custom_canvas\structure\custom_canvas.ass...      
-FATAL- mesh definition vertex node influences count invalid: #-4069 negative
-FATAL- mesh definition vertex texcoords count invalid: #-6750 negative
-FATAL- couldn't parse definition #0
-FATAL- couldn't parse file 'data\levels\multi\custom_canvas\structure\custom_canvas.ass'
-ERROR- structure import pipeline failed for levels\multi\custom_canvas\custom_canvas
```

#### Technical Root Cause
In ASS (Amalgam Scene Specification) version 3 (the geometry format consumed by Halo 3's structure pipeline), vertex definitions consist of:
1. Position: `X Y Z` (3 floats)
2. Normal: `I J K` (3 floats)
3. Node influences count: `0` (1 integer)
4. Texcoord count: `N` (1 integer)
5. Texcoords: `U V` (2 floats per UV; **not** 3-tuple `U V 0.0`)

Vertex colors (`R G B`) were only introduced in ASS version 6+ (v6, v7). In previous versions of `AssExporter.cs`, vertex colors (`v.Color.X v.Color.Y v.Color.Z`) and 3-tuple UV coordinates (`u v 0.0000000000`) were unconditionally serialized regardless of the version parameter.

Because Tool was instructed via the header to parse an ASS v3 scene, Tool's parser expected an integer node influences count immediately following the vertex normal. Instead, it consumed the vertex color float. As tokens became desynchronized across vertices, Tool read subsequent vertex coordinate floats (e.g. `-4069.1489257812` and `-6750.0000000000`) as the node influence count and texcoord count. Because these values were negative floats cast to integers, Tool aborted immediately with `-FATAL- negative count`.

#### The Fix
- **`AssExporter.cs`**:
  - Guarded vertex color serialization with `if (version >= 6)`. In ASS v3, vertex color lines are omitted.
  - Guarded 3-tuple UV coordinates with `if (version >= 5)`. In ASS v3, UVs are output as standard 2-tuple `u v` without extraneous padding floats.
  - Named mesh object headers with `"{obj.Name}"` rather than anonymous empty strings.
- **`AssImporter.cs`**:
  - Updated vertex parser with `if (headerVersion >= 6)` to conditionally consume vertex colors, ensuring seamless round-trips for both ASS v3 and ASS v7 files.
- **`MainViewModel.cs`**:
  - Added `levelName: ActiveLevelName` to the 1-Click Compiler export call, ensuring material sanitization properly prepends the active level collection prefix.
- **`ForgeWorksTests.cs`**:
  - Added unit regression test `AssExporter_AssV3_DoesNotWriteVertexColorsOr3dUVs_FixingToolNodeInfluencesFatalError`.
  - Updated `AssExporter_ExportsVertexColorsInVersion7` to verify vertex colors in ASS v7 format.
